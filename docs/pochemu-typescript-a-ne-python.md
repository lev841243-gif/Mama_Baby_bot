# Почему TypeScript, а не Python

Коротко: главный интерфейс проекта — мини-приложение в Telegram, а оно пишется только на JavaScript. Если писать сервер и бота на том же языке, весь проект живёт на одном стеке и на общем коде.

## Главные причины

1. **Один язык на всё.** Мини-приложение (React) — JS/TS в любом случае. С Python было бы два языка, две сборки, два набора зависимостей и два CI. Сейчас мини-приложение, сервер, бот и админка — один TypeScript, один `pnpm install`, один Dockerfile.

2. **Общий код без дублирования.** Пакет `packages/shared` используют и бот, и сервер, и мини-приложение. В нём типы согласий, тексты, правила возраста, проверка «красных слов». С Python эти правила пришлось бы писать дважды и следить, чтобы они не разошлись. Для ТЗ это важно: правило «без согласия ничего не пишем» должно работать одинаково везде.

3. **Админка «из коробки» внутри того же приложения.** Payload CMS работает внутри Next.js. Версии, черновики, отложенная публикация, загрузка в S3 и русский интерфейс там уже есть, а это ровно то, что ТЗ 9.4 требует от админки автора. В Python ближайшая замена — Django admin: он хороший, но версии и отложенную публикацию в нём собирают из сторонних пакетов, а мини-приложение всё равно остаётся отдельным JS-проектом.

4. **Экосистема Telegram Mini Apps — на JS.** SDK мини-приложений, готовые компоненты в стиле Telegram (`telegram-ui`), проверка подписи данных запуска (`init-data-node`) — это всё пакеты для JavaScript.

5. **Типы от базы до экрана.** Схема базы (Drizzle) → серверные функции → ответ API → экран: TypeScript проверяет всю цепочку. Если поле переименовали, сборка упадёт сразу, а не у мамы в приложении. В Python есть подсказки типов и pydantic, но они заканчиваются на сервере, и до фронтенда проверка не доходит.

## Где Python не хуже

- **Бот.** Библиотека aiogram 3 не уступает grammY. Будь проект только ботом, Python был бы нормальным выбором.
- **Скорость.** При 5–5 000 пользователях разницы нет: оба стека справятся.
- **ИИ-сервисы.** SpeechKit, YandexGPT, GigaChat и Claude вызываются по HTTP, на любом языке одинаково. pgvector — это SQL.

## Где Python лучше, и что мы с этим делаем

- **Русская морфология.** У Python есть `pymorphy3`, он точнее разбирает формы слов, чем стеммер Snowball. Для «красных слов» мы закрываем это стеммером, поиском опечаток и списком форм от автора: ТЗ разрешает лишние срабатывания, а пропуски — нет. Если точности не хватит, можно добавить маленький Python-сервис, который получает задачи из той же очереди.
- **Машинное обучение и анализ данных.** В проекте их нет: ИИ работает через внешние сервисы, а сводка для автора — это SQL-агрегаты.

## Итог

TypeScript дал один язык и общий код для бота, сервера и мини-приложения, а ещё готовую админку внутри Next.js. С ним проект проще сопровождать одному разработчику и проще передать заказчице: один репозиторий, одна сборка, один `docker compose up`.
