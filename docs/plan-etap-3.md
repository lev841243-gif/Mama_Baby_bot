## Главное правило этапа

ИИ на этапе 3 появляется у мамы впервые, поэтому граница описана заранее (ТЗ 3.1, 10.1, 10.7):

## Шаг 5. Голосовой поиск в боте ☐

Цель: голосовое → мама видит распознанный текст → «Найти материалы» → 1–3 материала. Ни аудио, ни текста не остаётся.

- Голосовое (ТЗ 6.4, 10.2) работает, если есть основное согласие с п. 8 (шаг 1) или согласие на календарь. Без них — предложение, аудио не скачивается. Лимит 60 с, распознавание ≤ 10 с — как на этапе 2.
- После распознавания:
    - «красные слова» — экстренный текст, больше ничего (приёмка 20, 25);
    - иначе «Распознано: „…“» и кнопки: «Найти материалы», «Записать в календарь» (если календарь включён и есть согласие на него), «Исправить».
- **[решение Л6]** Текст не держим нигде: поиск и разбор календаря выполняются сразу после распознавания. В кнопки кладутся только ID найденных материалов (`vs:12.45.78`) и черновик календаря, как сейчас (`cal:v:…`). «Найти материалы» показывает уже найденное, лимит списывается при нажатии. «Исправить» — мама пишет текстом, дальше обычный поиск.
- Календарь: путь «Записать навык» → голос не меняется. Голосовое «с улицы» без календаря — только поиск.
- **[заглушка Р3]** Микрофона в мини-приложении нет: на экране поиска подсказка «Можно спросить голосом в боте».
- Логи: хеш ID, провайдер, время распознавания и поиска. Ни текста, ни `file_id`. Тест «после голосового поиска в базе, Redis и логах нет ни аудио, ни текста» (приёмка 30).

ТЗ 6.4, 10.2, 10.3, 11.4, 13 (≤ 10 с); приёмка 20, 22, 30.

**Готово, когда:** на сервере с настоящим сервисом речи голосовое «не спит днём, что делать» показывает распознанный текст до поиска, «Найти материалы» даёт 1–3 материала; после этого в базе, Redis и логах нет ни аудио, ни текста.

## Шаг 6. Помощник автора в админке ☐

Цель: подсказки автору по тексту материала. Мама их не видит, публикует только автор.

- **[заглушка Р4 / вопрос Л11]** Провайдер для генерации — по решению Веры: облачная модель в РФ (YandexGPT, GigaChat) или Claude. В помощник уходят только тексты автора, данных мам там нет (ТЗ 10.5). Задачи идут через очередь `ai`, ответы проверяются Zod. Без ключей — фейковый провайдер, панель показывает «Помощник не настроен».
- Панель «Помощник» в карточке материала (кнопка «Предложить», не автоматически):
    - **теги и навыки** — выбор только из словаря тегов и справочника навыков. ИИ не создаёт новых. Подсказка через ближайшие по векторам материалы (шаг 2) и генерацию. Автор отмечает галочками, что принять;
    - **черновик анонса** 2–3 строки — генеративный. Поле анонса не заполняется само: текст лежит рядом с кнопкой «Вставить», и автор правит его до публикации (ТЗ 3.1: маме уходит только утверждённый автором текст). Слова, которых нет в тексте материала, подсвечиваются — как при сборке из канала (diff-match-patch);
    - **проверка опасных формулировок** — диагнозы, дозировки («мг», «капли», «раз в день»), «не ходите к врачу», сравнения с нормами («уже должен», «отставание», «рано/поздно» — правило 3.4). Два слоя. Первый — правила по списку автора (как «красные слова», стеммер), работают и без ИИ. Второй — ИИ-проверка с цитатой найденного места. Показываются предупреждения, публикацию они не запрещают. Проверка запускается и при сохранении черновика.
- **«Чего не хватает»** в «Сводке»:
    - темы «чего ищут, но нет» (`stat_wanted_topic`);
    - пустые и маленькие разделы (меньше 5 материалов, Р11);
    - навыки справочника без упражнений;
    - промахи теста «25 из 30».

    Это агрегаты без данных мам (ТЗ 11.3). ИИ здесь не обязателен — по желанию Веры кратко группирует темы.
- Журнал админки (ТЗ 13): «принята подсказка помощника» — кто и когда, без текста подсказки.
- Роли: панель видят автор и исполнитель. Исполнитель тексты не меняет (ТЗ 4).
- Тесты: предложенный тег вне словаря отбрасывается; опасная формулировка из списка находится в другой форме слова; анонс без нажатия «Вставить» не попадает в материал.

ТЗ 3.1, 3.2, 3.4, 4, 9.6, 9.7, 10.5, 10.7, 11.3; правило 1 CLAUDE.md.

**Готово, когда:** Вера на своём материале получила теги, навыки и черновик анонса, приняла часть одной кнопкой, увидела предупреждение на «дайте 5 капель» и опубликовала сама; без её действий в материале ничего не поменялось.

## Шаг 7. Потолок расходов и устойчивость ☐

Цель: расходы на ИИ не выходят за месячный потолок Веры, сбой сервиса не ломает поиск.

- Таблица `app.ai_usage` (обезличенно, без `user_id`): месяц, сервис, задача (`embed-query`, `embed-material`, `transcribe`, `assistant`), единицы, сумма в рублях по тарифу из настроек. Своя модель на сервере — расход 0, счётчик вызовов остаётся.
- Потолок из «Настроек проекта» (ТЗ 10.1). При 80% — алерт исполнителю и, по желанию, автору. При 100% поиск мамы переключается на поиск по словам до конца месяца. Голос для календаря и помощник автора — по отдельным переключателям («при потолке выключать»), по умолчанию выключаются.
- «Сводка»: расход за месяц по задачам, число запросов «по смыслу / по словам / откат».
- Таймауты и автоповтор для индексации материалов (очередь `ai`, BullMQ backoff). Запрос мамы не повторяется, при сбое сразу откат на поиск по словам.
- Нагрузка (Р14, до 5 000 мам): своя модель — замер времени вектора на 2 vCPU и памяти контейнера, рядом с web и worker. Облачная — лимиты запросов в секунду у сервиса.

ТЗ 10.1, 10.6, 13 (надёжность, алерты), 14; Р14.

**Готово, когда:** при искусственно низком потолке поиск сам переходит на слова и приходит алерт; в «Сводке» виден расход за месяц; остановка сервиса векторов не даёт ошибок маме.
