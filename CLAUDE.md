## Стек

- **pnpm workspaces**, TypeScript везде, Node 24.
- `apps/web` — Next.js 15 (App Router), `output: 'standalone'`, без Vercel-специфики. Внутри — **Payload CMS 3** (админка автора: версии, черновики, отложенная публикация, `@payloadcms/storage-s3`, sharp) и мини-приложение (`/app`), API мини-приложения (`/api/tma/*`).
- Мини-приложение: React, `@telegram-apps/sdk-react`, `@telegram-apps/telegram-ui`, Tailwind, TanStack Query, Embla Carousel. Проверка initData на сервере — `@telegram-apps/init-data-node`.
- `apps/worker` — бот **grammY** (плагины conversations, menu, transformer-throttler, auto-retry) + **BullMQ** на Redis (очереди: лента, напоминания, посты канала, ai).
- `packages/shared` — схема БД `app` на **Drizzle** (+ drizzle-kit миграции), общие типы, Zod-схемы, «красные слова», тексты по умолчанию, утилиты (возраст, хеш ID).
- PostgreSQL 16, Redis 7, Caddy (HTTPS), всё в **Docker Compose**, настройки только через env.
- Хранилище файлов — S3-совместимое в РФ (например S3 Beget).
- Поиск по смыслу (этап 3) — своя модель векторов в контейнере `embed` (text-embeddings-inference, `intfloat/multilingual-e5-small`, 384), pgvector в своём образе Postgres (`infra/postgres`), векторы — `app.material_vectors`, сверка раз в 2 минуты в очереди `embed` (`shared/embed.ts`).
- Мониторинг: GlitchTip (через `@sentry/nextjs`), Uptime Kuma, pino. Деплой — GitHub Actions. Бэкап — ежедневный `pg_dump` в S3, хранение 30 дней.

## База данных

- Две схемы: `payload` — контент (управляет Payload), `app` — данные мам (Drizzle).
- **Данные мам НЕ кладём в коллекции Payload.** Автор видит только обезличенную сводку (ТЗ 11.3) — агрегаты, без отдельных мам.
- Все таблицы мам ссылаются на `app.users` с `ON DELETE CASCADE`, **кроме `payments`**: запись остаётся, `user_id` обнуляется (`ON DELETE SET NULL`).
- Telegram ID — `bigint`. В логах — только хеш (HMAC с секретом из env), никогда открытый ID, username, имя, текст запроса.
- `consents`: тип, версия, время выдачи, время отзыва. Каждый пункт окна согласий — отдельная запись (ТЗ 6.6, 8.9).
- `users.is_tester` + таблица `access_list` (закрытый режим, ТЗ 14).
- `feed_sent`: уникальный индекс `(user_id, material_id)` — материал не уходит дважды.
- Обезличенная статистика (ТЗ 11.2) — отдельные таблицы-счётчики без user_id.
- Миграции в CI строго по порядку: **сначала Payload, потом drizzle-kit**.
- Правки автора, нужные боту (тексты, «красные слова», версии согласий, настройки), хуки Payload пишут в `app.app_settings`; `getConfig()` в shared читает их с TTL 30 с, живой объект `T` — тексты. Хуки сида пропускают это по `req.context.seed`.
- Медиа маме — только по подписанным ссылкам `/api/m/:id/:variant` (`lib/media-url.ts`), выдаются после проверки доступа к материалу. Коллекция `media` закрыта для всех, кроме админки.

## Правила из ТЗ, которые влияют на код

1. **ИИ ничего не пишет маме от себя** (ТЗ 3.1–3.2, 10.7). Маме показываются только тексты автора и утверждённые шаблоны. В поиске для мамы генеративная модель не используется. При сборке статей из канала ИИ только группирует; текст, которого нет в постах, подсвечивается (diff-match-patch).
2. **Никаких норм и сравнений** (ТЗ 3.4): ни в UI, ни в справочнике навыков, ни в подборе. Слов «отставание», «уже должен», «рано/поздно» нет.
3. **Минимум данных** (ТЗ 3.5, 11.4). Не хранить: имя, username, телефон, текст поисковых запросов, голос и его текст, отметки подбора «Что уже умеет малыш?» (без календаря), точную дату рождения, данные карт, переписку. Новое поле с данными мамы = решение заказчицы + новая версия согласия.
4. **Без основного согласия** (нет записи или устарела версия) любое действие в боте и любой запрос мини-приложения ведёт в окно согласий; ничего не записывается (ТЗ 6.1, 8, приёмка 1–2).
5. **Окно согласий** (ТЗ 8.9): галочки сняты по умолчанию; «Принять всё» отмечает только показанные пункты; «Продолжить с выбранными» активна только с первым пунктом; «Не сейчас» без первого пункта — ничего не пишем. Показываются только работающие функции (календарь — с этапа 2, новости автора — только если Р6 «да»).
6. **Отзыв согласия** (ТЗ 6.5, 11.5): подтверждение → физическое удаление всех данных мамы (CASCADE), кроме payments. Повторный /start — вход с нуля.
7. **«Красные слова»** (ТЗ 10.3): проверка **до любого действия** (поиск в приложении, текст и голос в боте, календарь). Русский стеммер (snowball-stemmers) + опечатки (fastest-levenshtein) + список автора. Лишнее срабатывание допустимо, пропуск — нет. Ответ — фиксированный текст автора с 103 и 112.
8. **Закрытый режим** (ТЗ 14, env `CLOSED_MODE`): **28.10.2026 Лев решил на время разработки открыть бот всем** (`CLOSED_MODE=false`); все вошедшие в это время помечаются `is_tester` (`TESTER_PHASE=true`) и удаляются перед бета-тестом. Перед бета-тестом с мамами режим включается обратно. Пока режим включён, бот и мини-приложение работают только для `access_list`. Остальным — «Бот пока в разработке» со ссылкой на канал, **о них ничего не записывается** (даже в логи — только хеш). Бета-дисклеймер: в приветствии, в /help, плашкой в приложении и над окном согласий. Режим и плашка переключаются в админке. Кнопка «Удалить данные тестировщиков» удаляет данные `is_tester`, не трогая контент.
9. **Подписка** (ТЗ 8.6): доступ к закрытым материалам, картинкам и аудио проверяется на сервере, в том числе по прямым ссылкам, в ленте и «Прислать в чат». Обработка оплаты идемпотентна.
10. **Тексты интерфейса пишет автор** (ТЗ 6.8): все тексты бота и приложения — из админки (Payload global), в коде только значения по умолчанию из юр. шаблона 07.
11. Возраст в **полных месяцах**, нижняя граница включается, верхняя нет; материал попадает во все пересекающиеся разделы (ТЗ 5).
12. Под каждым материалом: «Материалы автора. Не заменяет консультацию врача».
13. Правка контента видна в приложении и боте ≤ 5 минут без перезапуска (кеш с TTL/ревалидация).
14. Админка: вход с **2FA** (ТЗ 13; встроенной в Payload нет — плагин или otplib), журнал действий, роли автор/исполнитель.
15. ИИ — единый интерфейс провайдеров (`transcribe`, `extract`, `embed`, `complete`) через очередь `ai`, ответы валидируются Zod. Тексты мам — только сервисы РФ (SpeechKit, YandexGPT, GigaChat); для постов канала можно Claude. Импорт .docx — mammoth.js, OCR каруселей — Yandex Vision.
16. Поиск: этап 1 — полнотекстовый Postgres (`russian`), этап 3 — pgvector.
17. **Без Яндекс Метрики и Google Analytics.**

## Мобильные требования мини-приложения

Макеты 360–390 px; safe area; BackButton, MainButton, HapticFeedback; `disableVerticalSwipes` на экране упражнения; системные шрифты; MP4 вместо GIF; `next/image` на своём сервере; JS первого экрана ~150–200 КБ gzip; LCP < 2,5 с на 4G. Светлая/тёмная тема Telegram, крупный шрифт. Открытие вне Telegram — «Откройте через бот». Тесты на реальных iPhone и Android через cloudflared tunnel; Eruda — только для `access_list`.

## Команды

pnpm запускается через corepack (глобальных шимов нет): `corepack pnpm …`.

```
cp .env.example .env                 # заполнить BOT_TOKEN, секреты, ACCESS_LIST_TG_IDS
docker compose up -d --build         # postgres, redis, migrate → web, worker, caddy
docker compose --profile tunnel up -d cloudflared   # временный https для телефона

# локальная разработка
docker compose -f docker-compose.yml -f compose.dev.yml up -d postgres redis   # порты 55432, 56379
corepack pnpm dev:web
corepack pnpm dev:worker
corepack pnpm typecheck
# тесты (DB-тесты пропускаются без TEST_DATABASE_URL; пишут только отрицательные tg_id)
TEST_DATABASE_URL=postgres://mama:<пароль>@localhost:55432/mama corepack pnpm test

# миграции
corepack pnpm -F @mama/web payload migrate:create <name>   # после правки коллекций Payload
corepack pnpm -F @mama/web generate:importmap             # после новых компонентов админки
corepack pnpm db:generate                                 # после правки packages/shared/src/db/schema.ts
```

- Сервер (Beget VPS, `/opt/mama`): обновление — `bash infra/deploy/update.sh`, откат — `bash infra/deploy/rollback.sh`, подробно — [docs/14-razvertyvanie-na-servere.md](docs/14-razvertyvanie-na-servere.md).
- Мониторинг, алерты, бэкап (`infra/backup/backup.sh`, `restore-check.sh`), CI и ручной деплой из GitHub Actions — [docs/15-ekspluatatsiya-bekapy-i-monitoring.md](docs/15-ekspluatatsiya-bekapy-i-monitoring.md). Проверка здоровья — `/api/health`.
- Сервис `migrate` в compose прогоняет `payload migrate`, затем drizzle-миграции и добавляет `ACCESS_LIST_TG_IDS` в `app.access_list`.
- `next build` на Windows падает на шаге standalone (нет прав на симлинки) — это нормально, собирать в Docker.
- Мини-приложение: `/app`, API: `/api/tma/*` (заголовок `Authorization: tma <initData>`), юр. страницы: `/terms`, `/privacy`, `/consent`, `/rassylka`, `/oferta`, админка: `/admin`.
